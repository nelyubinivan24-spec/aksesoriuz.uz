# Catalog Structure

## Purpose

Define a scalable product catalog structure that supports:

- B2B discovery;
- SEO landing pages;
- industry-based navigation;
- product filtering;
- quote-based conversion;
- future product expansion.

## Catalog Strategy

The catalog should not be a flat list of categories. It should support three views:

1. By industry.
2. By product type.
3. By material or production technology.

Products can belong to multiple groups.

Example:

A menu folder may appear under:

- restaurant accessories;
- hotel accessories;
- eco-leather products;
- UV printing;
- embossing;
- menu covers.

- menu covers and menu folders;

- check boxes;

High.

## Product Data Requirements

Each product should support:

- product name;
- product code/SKU;
- short description;
- category;
- subcategory;
- industries;
- materials;
- branding methods;
- colors;
- dimensions if available;
- MOQ if available;
- production timeline if available;
- gallery images;
- related products;
- related services;
- SEO title;
- SEO description;
- inquiry CTA label.

## Product Card Requirements

Catalog cards should show:

- image;
- product name;
- short category/use case;
- material tags;
- branding method tags;
- CTA: Request calculation;
- optional CTA: Order sample.

Do not show:

- generic "Buy" buttons;
- placeholder prices;
- placeholder products;
- irrelevant demo content.

## Product Detail Page Requirements

Sections:

1. Product hero:
   - image gallery;
   - name;
   - category;
   - short commercial description;
   - CTA.
2. Key specs:
   - materials;
   - branding methods;
   - dimensions;
   - colors;
   - MOQ and timeline when confirmed.
3. Use cases:
   - who it is for;
   - where it is used.
4. Customization:
   - logo;
   - color;
   - material;
   - finishing.
5. Related products.
6. Related services.
7. Quote form.

## Inquiry List

Instead of a cart, use an inquiry list:

- add product to inquiry;
- continue browsing;
- submit one calculation request for multiple products.

This supports B2B buying without checkout/payment complexity.

## Category Page Content

Each category page should include:

- H1;
- commercial intro;
- category benefits;
- product grid;
- relevant filters;
- material/branding explanation;
- FAQ;
- quote CTA.

## Catalog Acceptance Criteria

Catalog structure is accepted when:

- all existing product types can fit into it;
- new products can be added without changing navigation;
- users can browse by industry and product type;
- SEO category pages have clear targets;
- product pages can support quote-first conversion;
- no direct checkout assumptions are required.
